# 外科病理报告（結直腸）模板设计说明

> 交付物：`report-engine/templates/pathology_colorectal.json`（声明式模板，可热改）
> 示例产物：`outputs/示例报告/pathology-colorectal/`
> 样本来源：使用者提供的 `SampleReport.zip`（10 份 docx，每份为 3 页扫描件）

## 1. 样本结构（10 份一致）

每份 docx 的可见文本只有「病例号 + `DIAGNOSIS:` 标题」，实际内容全在 3 张扫描页图片里，结构完全一致：

```
<病例号>
① Synoptic 汇总块（16 项，逐行「标签: 值」）
   Tumour site / Operative procedure / Histological tumour type / Histological tumour grade /
   Tumour dimension / Perforation / Relation of tumour to anterior peritoneal reflection /
   Plane of mesorectal excision / Extent of invasion / Lymphatic and venous invasion /
   Perineural invasion / Lymph node status / Tumour deposits /
   Proximal margin / Distal margin / Circumferential margin
② MACROSCOPIC EXAMINATION:  叙述段落（分件 1) 2)、取材者缩写、蜡块 A–N、尺寸 cm）
③ MICROSCOPIC EXAMINATION:  叙述段落
④ DIAGNOSIS:                标题（10 份样本正文均为空）
```

## 2. 模板字段表（20 项，行序与样本一致）

| # | 字段 key | 报告标签（英，与样本一致） | 中文标签 | section | 必填 | 允许兜底 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `case_number` | Case No. | 病例編號 | O | 否 | 否 |
| 2 | `tumour_site` | Tumour site | 腫瘤部位 | O | 是 | 否 |

模板级设置：`pool_all_sections = true`、`field_separator = " "`、`language = "en"`（导出表头与占位符走英文）。

**为什么需要 `pool_all_sections`**：默认按 `section` 分区池化（S/O/A/P 各一个池），而病理报告的内容天然跨「主观/客观/评估」——
所有 synoptic 项都是客观事实（O），诊断属评估（A），叙述段落又混在一起。整池匹配后不再受分区限制，
章节改由**标题**划分（见下）。同时该开关会强制保留未分类句子，避免病理叙述被 SOAP 抽取规则丢掉（实测 27 句中 16 句属 `uncategorized`）。

## 3. 取值规则（优先级从强到弱）

1. **章节标题**：整句等于 `scope_headings` 之一（如 `Macroscopic examination.`）→ 切换当前作用域，标题句本身**不进字段值**；
2. **`标签: 值` 直配**：句子以某字段的关键词/标签开头（取最长匹配）→ 值只保留冒号之后的内容，标签不重复出现在报告里；
   兼容打字习惯：`Tumour site: sigmoid colon` / `Tumour site is sigmoid colon` / `Case No.: SP-2026-004521` 均识别；
3. **作用域归属**：标题之后的句子归入该字段（叙述段落靠这一条整体归位）；
4. **关键词最强匹配**：无标题、无标签时按命中关键词长度挑选最具体字段；
5. **受托兜底**：`accepts_fallback=false` 的字段（16 项 synoptic + 病例号）**绝不**领取无关内容，
   未被口述覆盖就如实写「未提及」并进入缺失清单，阻断签署（BR-03 / BR-10）。

### DIAGNOSIS 段的自动生成（`compose`）

按确认的口径，诊断文字**由引擎生成草稿**，模板里声明：

```json
"compose": {
  "pattern": "{tumour_site}, {operative_procedure}: {tumour_grade} {tumour_type}, {extent_of_invasion}.",
  "required_keys": ["tumour_site", "tumour_type", "extent_of_invasion"]
}
```

- **只在医生没口述诊断原文时生效**；口述/粘贴的诊断原话优先采用（FR-07 原值保留）；
- 只做「连接已有字段值」，不推断、不补全、不加新事实；
- 生成结果带来源引用（拼接各字段的来源片段）与 `[自动生成，请核对]` 标记，医生仍需采纳/编辑后才能签署（BR-10 不放宽）；
- `required_keys` 任一为「未提及」时**放弃生成**，如实留占位符并写明缺哪一项，继续阻断签署（BR-03）。

示例输出（`outputs/示例报告/pathology-colorectal/`）：

```
DIAGNOSIS: Sigmoid colon, laparoscopic anterior resection: moderately differentiated
adenocarcinoma, not otherwise specified, tumour invades through muscularis propria into subserosa.  [auto-generated]
```

每个要素最多归属一个字段，字段带来源片段与时间点（NFR-12 可追溯）；

## 4. 复现验证（合成口述，非真实病例）

`scripts/smoke_demo.py out --template pathology_colorectal` 用合成口述（27 句，`app/main.py:SAMPLE_SEGMENTS_PATHOLOGY`）跑通全链路：

- 抽取 28 个要素（其中 16 个 `uncategorized`，靠整池 + 标签直配归位）；
- 20 个字段全部命中且值精确（例：`Tumour site: sigmoid colon`、`Lymph node status: 2 out of 16 lymph nodes show metastatic carcinoma`）；
- 三个切缘字段互不串内容（6.0 / 4.5 / 1.2 cm 各归其位）；
- 宏观段不含镜下描写，镜下段不含宏观描写，`Macroscopic examination` 标题句未污染字段值；
- 医生未口述诊断原文时，`DIAGNOSIS` 段由模板按 5 个已抽取值拼装，带 `[auto-generated]` 标记；
- `缺失必填：无`，签署 `ok=True`，导出 `text/json/pdf/html` 四格式；
- 英文导出行样式与样本一致：`标签: 值`（ASCII 冒号），表头/占位符本地化为英文（`Not mentioned`）。

自动化断言见 `tests/test_pathology.py`（10 项）；全量 `pytest -q` = 22 passed；exe 侧同样跑通
（`scripts\http_smoke.py --exe report-engine\dist\medscribe-report-engine.exe` 内含病理报告全链路）。

真实样本图片与提取文本仅留在 `.deepworks/tmp/`（工作区临时目录，不入库、不进交付物），
模板与测试中的病史内容全部为合成数据（NFR-05）。

## 5. 已确认口径（2026-10-20）

| 问题 | 结论 |
| --- | --- |
| 报告类型范围 | 病理报告为本次主类型，**同时保留** `general_soap`、`outpatient_record`（未注册模板仍自动兜底） |
| 病理科输入形态 | **口述转写**（`Tumour site: sigmoid colon...`），引擎按标签直配 + 标题作用域归位；粘贴成稿文本同样可用 |
| `DIAGNOSIS` 段来源 | **引擎自动生成诊断句草稿**（`compose`），医生核对后确认；缺关键项时不生成、继续阻断签署 |

> 其余两点如后续调整，只改 `templates\pathology_colorectal.json` 即可，无需改代码。

## 6. 如何自行调整

```bat
:: 1) 直接改模板（字段增删、改必填、改关键词、调行序）
notepad templates\pathology_colorectal.json
:: 2) 免重启热加载（服务运行中即可生效）
curl -X POST http://127.0.0.1:8790/api/reload
:: 3) 立刻用合成口述复跑，检查字段归位
report-engine\.venv\Scripts\python.exe scripts\smoke_demo.py report-engine\docs\demo-output --template pathology_colorectal
```

字段属性含义见 `docs/report-engine.md`「模板扩展」一节。
