## 1. 项目摘要

**项目名称**：MedScribe HK —— 香港临床口述智能病历助手

**一句话描述**：医生用粤语、英语或中英混合口语口述诊疗过程，系统完成"用户登录（角色选择式）→ 多语言转写 → 临床要素抽取（内部步骤）→ 模板化结构化报告生成 → 初稿预览与导出"的闭环，输出符合医院报告规范的病历初稿（**一期不含校审与签署，输出带"未校审"标识**）。

**核心价值主张**：把 3–5 分钟的口述变成 **1 分钟内可审阅**的病历初稿，且不改变医生现有的书写与审阅习惯。

> 说明：上述"3–5 分钟口述"与"1 分钟审阅"是**待验证的目标值**（见 §3、§6 R-01），不是已实测结果。

## 2. 问题与目标用户

| 用户 | 说明 |
| --- | --- |
| **主要**：门诊 / 住院医生 | 英文撰写病历、口语混用粤英，看诊后需快速完成病历整理，每日多次 |
| **次要**：病案室 / 质控人员 | 检查病历完整性与模板合规性，退回不规范记录 |
| **受影响**：患者 | 希望医生把注意力放在问诊而非打字上，并确保健康数据被安全处理 |

**问题场景**：门诊接诊后、查房后或交班前，医生需把刚发生的诊疗过程整理成结构化病历／报告。

| 编号 | 问题描述 | 状态 |
| --- | --- | --- |
| P-01 | 键盘录入或模板填空占用问诊后时间，高峰期为每份病历数分钟 | 待验证（ASSUMPTION-01） |
| P-02 | 粤语 + 英语 + 中英混合病名/药名的表达，通用语音输入识别效果明显下降 | 待验证（ASSUMPTION-02） |
| P-03 | 模板随专科与报告类型而变，手工复制粘贴易漏项、错项（过敏史、剂量、随访） | 待验证（ASSUMPTION-03） |
| P-04 | 口述连续、口语化、非结构化，难以自动映射到 SOAP 临床要素 | 待验证（ASSUMPTION-04） |
| P-05 | 患者数据涉及隐私、安全与合规，须避免可识别信息流入不受控的第三方服务 | 已确认为设计约束 |

> **团队完整性声明**：P-01 至 P-04 目前均为**假设**。本项目**不设访谈与现场观察环节**，因此这些假设尚未被一手用户证据证实。本提案**不引用任何未经执行的访谈引语、受访者数量或市场规模数据**；如引用外部文献结论，将单独标注来源与访问日期。

## 4. 现有方案与差距

| 现有方式 | 已知局限 |
| --- | --- |
| 键盘直接录入 / 科室宏 | 速度受限于打字，重复性高 |
| 模板填空 + 复制粘贴 | 易残留旧信息、漏项 |
| 通用语音输入法 | 不做临床要素抽取、不做报告模板；混合语种与术语表现需实测确认 |
| 录音后重听整理 | 延迟高、重听耗时 |

> 不对任何具体产品的性能下断言；相关表现属于本项目需实测的项目之一（R-01）。

**差距（Gap）**：缺少把以下四件事串成完整闭环、且能在受控数据环境下运行的方案——① 多语言混合 ASR；② SOAP 临床要素抽取；③ 模板化报告生成；④ **医生校审闭环**（逐字段确认、可追溯、签署后导出）。第 ④ 项是通用工具普遍缺失的一环：生成结果若无法被医生高效核对，临床上即不可用。

## 5. 提议方案与 MVP 价值

**一期（7 周内交付）的完整用户任务**：

```
① 选择使用者角色 → ② 开启会话并口述 → ③ 多语言转写 → ④（内部）抽取 SOAP 要素
                                                              ↓
                    ⑦ 按模板导出（带"未校审"标识） ← ⑥ 初稿预览 ← ⑤ 模板化结构化初稿
```

**②至⑦构成一期闭环**；医生逐字段校审与签署（原 ⑤）**属二期**，因此一期输出为"未校审（未签署）"初稿，导出物与界面必须带该标识（BR-14）。第 ⑦ 步以"导出可粘贴文本 / PDF / FHIR 风格 JSON"替代真实 EHR 写入，以控制集成风险。

| 编号 | MVP 功能 | 期次 | 为什么最小可用 |
| --- | --- | --- | --- |
| **F6** | **用户登录（角色选择式）** | **一期（新增）** | 提供唯一入口与使用者标识；**仅角色选择、无密码校验，不构成认证与访问控制**（见 D-15、NFR-13） |
| F1 | 会话录音 + 多语言 ASR（含医学术语增强） | **一期** | 无可用转写，后续环节全部不成立 |
| F2 | 临床要素抽取（S / O / A / P） | **一期：报告生成内部步骤**／二期：独立可校审 | 从"一段文字"到"结构化信息"的关键一跳；一期不做独立界面 |
| F3 | 模板化结构化报告生成 | **一期** | 医生需要的是符合规范的报告，而非自由文本 |
| F4 | 医生校审界面（逐字段确认 / 编辑 / 签署） | **二期** | 临床安全的最后防线；一期以 BR-14 未校审标识作为临时补偿，**不得视为已满足临床安全要求** |
| F5 | 术语库管理 + 会话本地存档 | **二期**（一期仅内置基础词表 + 会话列表/删除） | 支撑 F1/F2 的领域词表，并提供可复现的评估数据 |

**不在 MVP 范围**：真实患者数据接入、EHR/eHRSS 实时对接、移动端 App、多说话人分离、模型微调、多专科模板全覆盖、**账号体系（真实认证）与公网部署**、自动诊断或治疗建议。完整排除理由见配套文件《MVP 产品需求文档》第 3 节；一期/二期归属以《MVP 产品需求文档》第 2 节为准（依据《决策与验证记录》D-14）。

## 6. 可行性与风险

| 维度 | 评估 |
| --- | --- |
| 时间 | **7 周**（课程确定排期），W1–W2 为技术验证 spike；完整任务拆分、门禁与缓冲见配套文件《7 周执行计划》 |
| 技能 | 具备 Python 与 Web 前端基础；**缺口**：粤语语音处理、临床术语知识，由企业导师 / 医生顾问补足 |
| 数据 | 不使用真实患者录音；使用团队录制的脚本化模拟口述（明确标注为非临床合成数据 [SYNTHETIC]） |
| 设备 | 1 台开发机（优先带 GPU）+ 麦克风；或使用云端 ASR 试用额度 |
| 预算 | ASR 与 LLM API 费用，设定每月上限并监控 |
| 外部依赖 | ASR 引擎、LLM API、医院报告模板样本 |
| 合规 | 遵守香港《个人资料（私隐）条例》(PDPO) 基本要求；MVP 不处理真实患者可识别信息 |

**最关键不确定性 R-01**：粤英混合医学术语的 ASR 可达精度未知；若字错率无法接近 15% 目标，整个链条失效。

**应对（W1–W2 spike）**：① 录制 ≥ 1 小时（含 20 分钟冻结回归集）、≥ 4 位说话人的模拟口述（粤语为主 / 英语为主 / 中英混合三类）；② 双人标注 + 分歧仲裁；③ 对 2–3 个候选方案**分语种**计算 CER/WER，不合并为单一数字；④ 若全部 > 25%，触发范围收缩预案——退化为"英语为主 + 粤语关键词"的受限场景，并在文档中说明降级理由。

| 其他风险 | 缓解措施 |
| --- | --- |
| R-02 LLM 生成遗漏或编造关键信息 | 强制人工校审；字段级来源引用；幻觉字段数目标为 0 |
| R-03 拿不到真实报告模板样本 | W1 即向企业导师书面提出；否则退化为公开可得的结构示例并标注为假设 |
| R-04 无一手用户证据（本项目不设访谈） | 以导师/助教书面确认 + 公开报告规范 + 团队试标注作为证据来源；在各交付物中如实标注证据强度局限，不夸大 |
| R-05 团队 5 人、任务量偏大 | 严格限制 MVP 范围，先跑通一条端到端细线 |
| R-06 API 成本或配额超限 | 设置调用上限与缓存；准备本地开源模型降级路径 |
